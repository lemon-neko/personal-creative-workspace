# 求职与学习

## 定位与状态

状态：🟡 一期可用。该模块把候选人事实、真实项目证据、主简历、职位要求、技能差距和阶段制 Agent 工程学习路线连接起来，但不抓取招聘网站、不自动投递，也不会在学习页加载时访问 GitHub 或模型。

## 页面入口

| 入口 | 能力 |
|---|---|
| `/career` | 主简历、定制简历与可行内编辑的投递进度表；辅助资料默认折叠 |
| `/career/profile` | 候选人档案与导入确认 |
| `/career/documents` | 私有文档管理 |
| `/career/projects` | 真实项目证据库 |
| `/career/resumes` | 兼容入口，跳转 `/career#resumes` |
| `/career/resumes/{id}` | 结构化编辑、私有照片、实时预览与双版本导出 |
| `/career/resumes/{id}/match/{job_id}` | 本地关键词覆盖与结构完整度报告 |
| `/career/jobs` | 兼容入口，保留搜索和状态筛选并跳转投递表 |
| `/career/jobs/{id}` | 职位详情、阶段时间线与技能差距 |
| `/career/jobs/{id}/submissions/{snapshot_id}` | 当时投递简历的只读快照与历史 |
| `/focus` | 本阶段的求职交付与面试准备；与长期 Agent 工程路线分开 |
| `/learning` | 单一五层 Agent 工程路线和阶段状态 |
| `/learning/history` | 只读查看旧路线、Commit、测试结果与复盘 |
| `/learning/maintenance` | 维护路线之外的技能和额外任务 |
| `/learning/campaigns/{id}` | 历史项目战役和证据 |

## 学习主线

```text
Agent 工程通用能力
→ 按模块组织
→ 按依赖顺序学习
→ 参考成熟开源项目
→ 手搓模块
→ 提交测试与复盘证据
```

默认页面只使用一套五层工程路线，不再并列展示“八层框架”和“四个阶段”：

1. **工程底座**：API、数据库、异步、Docker 和日志，作为已有基础，不计入进度。
2. **最小 Agent**：Model、Context、Tool、State 和 Stop。
3. **可靠 Runtime**：Loop、Sandbox、Approval、Trace 和 Recovery。
4. **状态化编排**：StateGraph、Checkpoint、Persistence 和 HITL。
5. **产品化交付**：RAG、Memory、MCP、Eval 和 Application。

后四层对应现有四个学习阶段，按掌握程度推进，不设置固定周期：

1. **手写最小 Agent**：不依赖框架，完成假模型、两个受限工具、最大步数、超时、轨迹和单元测试。
2. **拆 OpenHands**：研读 Loop、Runtime、Sandbox、权限、持久化和 Trace，手搓受限 Runtime、人工审批与轨迹回放。
3. **学 LangGraph**：掌握 State、Node、Edge、Checkpoint、Persistence 和 HITL，交付可暂停恢复的持久化工作流。
4. **看框架与产品化**：对照 AgentScope 与 Dify，整理架构笔记，并把 MCP 工具注册和权限层接入第三阶段项目。

主页面只修改阶段状态，不编辑 Commit、测试结果或私人复盘。已有证据继续保存在数据库并由 `/learning/history` 只读展示，状态更新不会覆盖这些字段。原 Open Deep Research、FastAPI Starter、Onyx、OpenHands 四周路线和 Agent Reliability Arena 战役只归档，不删除原有进度或证据。

## 求职与简历闭环

- 候选人档案只保存作者确认过的事实。
- 项目证据记录职责、技术栈、问题、行动、结果和量化证据。
- 作者从已有 PDF、DOCX、Markdown 或文本中明确选择一份，经本地提取预览和人工确认后建立唯一主简历；相同校验和的 DOCX 复用已有私有文档。
- 主简历使用结构化字段和受控单栏模板。默认技术社招版按“职业摘要、教育经历、专业技能、工作经历、项目经历、自我评价”组织招聘阅读顺序；ATS 基础版保留作者设置的区块顺序。两套模板共用同一份事实数据，不复制或改写内容。
- 工作经历按公司形成第一层、按岗位形成第二层；同一公司名的多条岗位记录在预览与 PDF 中稳定归组，并汇总任职时间。岗位成果中符合“方向 - 项目（技术）”形式的短行作为职责小标题显示，原始岗位顺序和正文保持不变。
- 项目经历按“项目标题、项目简介、技术栈、个人职责”显示。项目角色保留在标题行，项目简介与技术栈使用紧凑文字，个人职责使用条目列表。旧版 `description` 继续保留为兼容数据；只有作者在映射预览中确认后，预览、PDF、本地匹配和定制候选才优先读取新的三层字段。
- 国内版 PDF 使用当前选择的模板并可显示私有照片；无照片 ATS PDF 始终切换到解析友好的 ATS 基础版。编辑器实时预览、打印 HTML 和 PDF 使用同一套模板结构。
- 国内版页眉按联系方式与职业信息分成两行，使用本地内置的线性图标、短竖线和带羽白青起始段的横向分区线；ATS 版不输出这些视觉图标。
- 本地 JD 报告展示关键词覆盖、缺失词和结构完整度，不承诺通过真实 ATS。
- 岗位定制创建主简历的子版本，永不覆盖主简历、档案或项目证据。

## 投递维护

- 求职首页只展示简历工作室、定制简历和投递表；候选人档案、项目证据、私有文档、历史简历与旧版登记放在默认折叠的辅助资料中。阶段行动和学习模块保持独立。
- 一条记录对应公司与岗位的一次机会，同公司可录多个岗位。表格末行为空白记录，填写公司和岗位后自动创建，再补一行空白记录；网络重试通过同一创建标识复用已有记录。JD 可后补，地点、来源和档位在职位详情维护。
- 表格支持公司或岗位搜索、进度筛选，默认隐藏已归档。公司、岗位、进度、日期、下一步和备注直接在单元格中修改：文字失焦保存，进度和日期变更保存；每行显示保存状态。保存期间不重排、不跳转，重新筛选或刷新后按更新时间排序，同秒更新按新增顺序倒序。错误保留输入并支持重试，筛选或跳转前先完成待保存内容，失败留在当前页。
- 进度按待投递、评估中、已投递、笔试、一面、二面、终面、HR 面、Offer、未通过、已撤回、已归档维护。旧面试状态显示为“面试中（未分轮次）”，不会自动推断轮次。实际阶段变化才新增历史记录，允许手工跳转，不自动填写投递日期。
- 新建定制版选择已记录的岗位；无 JD 可复制主简历手工定制，本地分析、模型定制和人工模型任务需先补充 JD。
- 实际投递简历由简历列的独立“记录”操作保存，只允许主简历或该岗位的定制版。每次明确记录新增只读快照，普通投递字段保存不重复生成快照。快照保留正文、名称、Revision、模板、照片引用和记录时间；源简历后续编辑不改变已有快照，可查看全部投递版本。
- 自动保存使用 `PATCH /career/jobs/{id}`，仅允许投递表的七个字段，只写入本次提交的值；未提交资料保留。新增记录沿用 POST 并支持 JSON；原完整表单继续可用，无数据库迁移。
- 快照保存当时的内容及展示配置，不复原外部实际发送的 PDF 文件字节；旧数据不自动补造投递版本。

## 数据、模型与隐私

- 路线、阶段、阶段参考仓库、职位、技能和简历关系位于仓库外私有 `workspace.db`。
- 上传文档和简历照片使用随机存储名；照片只通过本地受保护路由读取。
- 学习页通过独立状态接口只修改目标阶段状态，不操作 GitHub，也不读取本地代码仓库。
- 个人助手只读取当前阶段、下一步和未完成 P0 能力，不读取完整私人复盘。
- 页面加载不会访问招聘网站、GitHub 或调用模型。
- 联系方式、结构化简历正文、投递快照和照片不进入全局搜索或手机快照。全局搜索只索引简历版本的标题、目标岗位和备注，以及选定的项目证据与职位字段；搜索和附件均限本机私有访问。

## 当前限制与失败处理

- 路线不会自动判断“是否真的掌握”；“已验收”由作者手工确认。
- 全新数据目录从空投递表开始，岗位由使用者手工录入。既有数据库中的职位和历史记录继续可用。
- 职位 A/B/C 档、投递日期与下一步由作者手工维护；页面按既有状态显示流程，不会自动投递或推断 Offer。
- 学历、论文、年限等非短期差距不会伪装成学习阶段。
- A2A/A2UI、微调和深入 K8s 保持 P2，不阻塞当前四阶段主线。
- 阶段保存使用事务；非法状态和不存在的阶段不会写入。
