# 日常工作与 AI 工作流

桌面工作台启用内置插件后，首页打开本机 Super Productivity 20.0.0 的月历。待办、项目、标签、子任务、计划、计时和工时都由 Super Productivity 管理。待安排表示待办尚未排日期，拖到日历后仍是原任务。日常工作默认使用简体中文，顶部可切换 English 或中文，刷新后保留所选语言。待办入口在两种语言下都叫 Inbox。侧栏隐藏「支持我们」入口。浏览器会记住选过的日、周或月视图。首次启用使用新的浏览器存储，不导入旧数据。

任务右键菜单中的「插件操作 → 交给 AI」只带入 ID 和标题。补充目标后，可检查外发的完整指令、任务材料及模型，再确认。重复点击原任务会打开已有工作项。在工作项里显式再次运行才会创建新轮次。

Agent Autoloop 1.8.1 负责规则派发、时间线、卡片和恢复。自动事件和定时规则只能创建待确认的工作项。回答卡片会先预览下一轮外发内容，确认后再继续。模型只经现有网关执行。候选产物留在工作台，人工验收后依旧可以查看历史产物。原任务完成状态由 Super Productivity 管理。

Super Productivity 与 Autoloop 分别启动。Autoloop 安装或执行后端配置出错时，日常工作和手机看板仍可用。Web 包校验失败时，首页提供旧待办入口，AI 工作流可继续处理已交接的工作项。

「设置 → 运行状态」分别显示日常 Web、Autoloop Hub 和 Worker 的健康情况。可单独重启日常 Web 或 Autoloop。

插件菜单提供旧待办、旧任务和旧执行记录，以及主线与分支、知识库、创作、求职等原功能。旧待办与旧执行链接仍能访问。

当前嵌入范围是完整 Web 版。云同步、外部 Webhook 和通知通道默认关闭。

## AI 工作流控制中心

`/tasks` 展示 Hub、Worker、Agent 和通道的独立状态。十二个观测环节可打开证据抽屉。清洗去重、上下文准备及回执解析标记为不可单独观测，并展示关联的真实上下游事实。Ask、Notice、Later、Events 与普通结果分开显示。运行摘要按真实状态筛选；「今日完成」是上游在规则时区内统计的 `done` 轮次。执行失败后排队的轮次保留失败次数，状态不确定的轮次单列。断线期间保留最后一次快照并标记过期；同源实时连接恢复后补齐变化。

事项按工作台关联或 Autoloop 的组与 lane 归并，名称只用于展示。点事项或轮次打开时间线，可查看实际领取、开始、回执、用量、定时复查、发出的事件，以及人工回答和关联续跑。没有被上报的时间、用量或推荐理由会明确标注。轮次结束、卡片关闭和工作台产物验收分别显示。历史支持按规则、Agent、状态、日期和事项搜索；筛选范围是已加载轮次，可继续向前加载。

待决策收件箱支持预设选项和文字回答；可处理的 Notice 必须填写结案原因，仅告知通知没有结案按钮。工作台的模型决策卡片仍从工作项进入，预览并确认下一轮模型调用。规则支持暂停、恢复、立即运行、查看配置摘要和执行历史。工作台不会重试不明结果的模型调用；上游没有独立的 Run 重试接口。

## DeepSeek Harness 执行后端

AI 工作流可以在本机配置 DeepSeek Harness。Autoloop 管理规则、队列、派发和人工决策，Worker 通过 ModelGateway 驱动 Harness。每次人工确认允许一次模型请求，发送当轮预览中展示的指令和任务材料。Harness 以隔离的临时会话运行，模型用量回写到 Autoloop 回执。收到 Ask 后，回答和下一轮预览一起确认，最终产物仍需人工验收。

归档边界可将旧事项和已结案的卡片移出当前控制中心。原工作项链接保留历史。同一个日常任务可重新交接为新事项。

事项抽屉支持切换执行轮次、决策卡片、定时器和事件。独立的执行历史和规则管理保留筛选与操作。终态轮次可按真实 Fact 序号播放、暂停、单步或拖动时间轴。Session 页面展示 Autoloop 系统事实、Harness SDK 生命周期及已保存的结果；缺少用量、工具或终端数据时明确标注。可见字段与局限见[可观测性审计](../development/workflow-observability.md)。
