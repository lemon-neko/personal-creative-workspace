# 收入面板

## 定位与成熟度

状态：🟡 一期可用。收入模块是一个完全本地、手工确认的收入与商业验证控制面。它在现有账本和单产品验证之上，加入“画像 → 需求证据 → 反诈核验 → 最小试验 → 实际复盘”，不负责自动发布、收款或同步平台订单。

主要入口：

- `/income`：收入概览、趋势、来源分布与四个收入来源。
- `/income/profile`：能力、时间、资金和目标画像。
- `/income/opportunities`：少量候选机会及验证状态。
- `/income/opportunities/{id}`：公开证据、反诈结论、冻结预测和复盘。
- `/income/entries`：新增、确认和查看收支记录。
- `/income/products/agent-reliability-launch-kit`：Money Engine V1 单产品控制面。

## Money Engine V1

第一阶段只激活一个数字产品：`羽白 Agent 应用可靠性上线包`，定价固定为 ¥9.9，目标用户是正在开发 Agent 应用的个人开发者。

交易链固定为：

`GitHub 免费精简版 → 公众号介绍 → 面包多付款与自动交付 → 手工确认真实到账`

工作台保存产品版本、三个公开 HTTPS 入口、下一步、手工漏斗快照和五张职责卡。它不保存第三方账号、订单身份、付款凭证或买家信息，也不运行后台 Agent。产品、流量、转化、交付和验证职责卡只用于说明每一步如何影响数字产品收入。

“第一笔 ¥1 已跑通”必须同时满足：陌生购买、无私聊销售、第三方付款、平台自动交付、退款期结束、订单未退款，并且关联的数字产品收入已经确认、净到账不少于 ¥1。任一条件缺失都只能显示“链路进行中”。

## 赚钱验证闭环

闭环参考 [cheat-on-money](https://github.com/XBuilderLAB/cheat-on-money) 的公开方法，使用工作台原生 Python 和 SQLite 重写，没有复制或运行其业务代码：

1. 画像：使用 T0–T3 表示当前能力边界，并记录时间、启动资金、地区、语言和目标。
2. 找需求：候选机会必须说清“谁为什么付钱”，教程、收益故事和流量热度不能单独作为需求证据。
3. 做核验：至少需要两个不同公开来源、两年内的证据，其中至少一个在一年内；同时记录交叉印证。
4. 反诈：A1–A6 是硬性红旗，出现任意一项会自动标记高风险并停止；B1–B6 保留为可疑信号。
5. 小步试钱：只有核验通过的机会才能冻结工时、首笔收入天数和收入区间预测，并记录最小验证步骤与止损条件。
6. 复盘：保存实际工时、实际结果、阻断点和继续/调整/停止结论。预测一旦冻结不可回改，防止事后美化。

工作台不替用户伪造证据。内置的“Agent 应用可靠性上线包”只是待验证假设，初始没有被标为可行。机会复盘中的收入是校准材料，不进入收入统计；“已赚到”仍只来自已确认账本。

## 四个固定收入来源

来源及顺序不可在页面中增加或删除：

1. 数字产品：模板、工作流、资料包与代码包，也是当前优先方向。
2. 情报订阅：按周或按月交付的精选数据与信息。
3. Micro-SaaS：解决单一具体问题的小工具。
4. 广告与 CPS：免费工具或内容带来的广告与成交分成。

每个来源只维护状态、当前产品、价格说明、安全 HTTPS 销售页和下一步。状态固定为未开始、准备中、售卖中和暂停。

## 记账与统计口径

收支类型固定为收入、费用和退款；现金状态固定为待确认、已确认和已作废。金额以人民币分保存，避免浮点误差。

- 实际到账：已确认收入的毛额减去该笔平台费用。
- 本月到账：本自然月发生的已确认净收入。
- 待到账：待确认收入的毛额减去预计平台费用。
- 累计扣减：已确认的平台费用、支出和退款。
- 净现金：实际到账减去已确认支出和退款。

待确认记录不进入实际到账，作废记录不参与任何统计。已确认记录不允许直接作废；发现错误时应新增一笔退款或费用，保留真实现金轨迹。

## 数据与隐私边界

权威数据位于仓库外 `workspace.db`：

- `income_sources` 保存四个固定来源的工作状态。
- `income_entries` 保存手工录入的收支记录。
- `money_engine_products` 保存唯一激活的首品及公开入口。
- `product_metric_snapshots` 保存累计漏斗手工快照。
- `revenue_role_cards` 保存五张固定职责卡。
- `revenue_validations` 关联收入记录并保存严格通关检查。
- `money_profiles` 保存唯一的本地赚钱画像。
- `money_opportunities` 保存候选、验证结论、最小计划和冻结预测。
- `money_evidence` 只保存公开 HTTPS 证据的最小摘要和日期。
- `money_retros` 保存预测后的实际结果和决策复盘。

账本不保存银行卡、支付账号、实名材料、付款凭证或账户标识。备注不进入全局搜索，整个收入模块不进入 Android PWA。

页面加载和保存不会联网、调用模型或执行外部写入。外部研究由作者或明确触发的 Codex 任务完成，再把可核验来源手工录入。个人助手只读取收入汇总、画像层级、当前候选的结论与下一步，不读取证据全文、复盘正文或账本备注。

## 迁移、失败与限制

收入极简化迁移在升级前创建数据库快照，随后删除已确认无有效记录的旧信号、机会、实验、悬赏和发现表，再创建新表。迁移和版本登记位于同一事务；失败时旧表和旧版本保持不变。

当前限制：

- 不接支付平台或订单系统。
- 不在工作台内扫描 GitHub、RSS、Gitee 或接单平台。
- 不计算自动化比例、市场机会分或实验指标。
- 不承诺收入，只记录作者确认过的事实。
- 不自动创建或发布 GitHub 仓库、公众号文章或面包多商品。
