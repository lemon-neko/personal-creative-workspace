# 工作台与内容

## 定位与状态

状态：✅ 已可用。该模块负责接住随想、生成中性周回顾、独立撰写文章，并维护归档、回收和本地搜索。完整类型关系见 [内容模型](../architecture/content-model.md)。

## 页面入口

| 入口 | 能力 |
|---|---|
| `/legacy/planner` | 旧待办：直接录入和处理待办，查看待确认运行以及主线与分支进展；顶部可打开全局检索，想法记录默认折叠。阶段数据详见[阶段行动](focus.md) |
| `/legacy/planner?board=upcoming` | 待安排：按日期查看未来待办或未排定的阶段行动，可放到今日 |
| `/?view=...`、`/?q=...` | 兼容旧首页筛选地址，在看板下显示原有随想创作流；`/partials/workspace-feed` 继续提供局部结果 |
| `/ideas`、`/ideas/{id}` | 只管理 `thought`，支持筛选、编辑、归档和整理为知识 |
| `/reviews`、`/reviews/{id}` | 只管理 `weekly-review`，生成中性周期汇总 |
| `/articles`、`/articles/{id}` | 独立创建和编辑 `article` |
| `/search`、`Cmd+K` | 本地检索内容、知识、求职、学习和视频元数据 |
| `/trash` | 恢复或二次确认永久删除 |

## 核心流程

1. 随想只要求正文；标题和摘要可以自动生成。
2. 旧待办页面的快速记录可选填标题、标签和分类；保存后显示反馈并跳到待整理的兼容筛选视图。随想可继续由桌面、Obsidian 或手机编辑。
3. 值得长期复用的随想可进入“整理为知识”；普通经历可以一直停留在来源层。
4. 周回顾按自然周汇总记录，默认使用确定性规则，不套用公众号文风。
5. 文章从文章区独立创建，不要求关联随想或知识卡。
6. 回收操作只移动目标文件；永久删除需要严格确认词。

## 数据与状态

- `ContentItem` Markdown 是随想、文章和周回顾的权威来源。
- 旧看板不读取跨模块统计；创作流筛选结果只在带 `view` 或 `q` 的旧地址显示。想法库继续承载完整随想列表。
- “待我确认”显示下个阶段决策和最多三条需处理的 AI 运行。没有阶段也能添加独立待办、交给 AI。文章默认显示清单，知识库默认从学科目录进入；维护工具按需展开。
- 底层状态固定为 `draft`、`published`、`archived`。
- 随想显示为待整理、已整理、已归档；文章显示为草稿、已成稿、已归档；周回顾显示为回顾草稿、已确认、已归档。
- 私有图片位于 `content/assets/`，通过受保护路由读取，不进入 `/static`。
- FTS5 只保存可重建索引；普通搜索请求不会触发全量重建。

## 模型、联网与隐私

- 保存、编辑、搜索和规则周回顾不调用模型。
- 手工创建周回顾模型任务时仍须经过外发预览和确认。
- URL、上传材料和 Markdown 原始 HTML均视为不可信输入。
- Obsidian 并发修改通过语义 Revision 检测，冲突返回 409，不静默覆盖。

## 当前限制与失败处理

- 归档内容不进入日常列表，但仍可通过管理页面恢复。
- 定时回顾依赖桌面服务处于运行状态，并且只能执行规则版。
- Markdown 单文件错误只生成诊断，不应阻断其他内容加载。
- 搜索异常可在 `/settings/search` 查看并显式重建。
