# 求职学习指南

## 建立可信档案

1. 在 `/career/profile` 维护目标岗位和已经核实的经历、技能、教育与证书。
2. 在项目证据库记录职责、技术栈、问题、行动、结果和量化证据。
3. 上传 PDF、DOCX、Markdown 或文本简历，在 `/career/resumes` 明确选择文件并查看导入候选。已经保存且校验和相同的文件会直接复用，不要重复上传。
4. DOCX 候选页会同时展示结构化文本、解析诊断和识别到的证件照；校对姓名、摘要、经历、教育、项目证据、技能和自我评价后，人工确认建立唯一主简历。
5. 后续档案或项目证据变化只会显示“待复核”；进入主简历确认需要同步的事实，不会自动覆盖原表达。
6. 所有模型提取结果都先预览和人工确认，不能自动修改候选人事实。

## 导出两种简历

- “国内照片版 PDF”使用 A4 单栏信息结构，并在右上角显示私有证件照。
- “无照片 ATS PDF”使用相同文字内容，但不读取或嵌入照片，适合机器解析或明确要求无照片的岗位。
- 两种版本均为即时生成，不默认保存导出副本；原始 DOCX、历史简历和主简历结构化数据彼此独立保留。
- 更换或移除照片只影响对应简历的照片引用，不修改原始 DOCX。岗位定制子版本默认继承主简历照片，但仍可选择任一导出版本。

## 跟踪职位

- 手工粘贴 JD 或上传文档，记录公司、岗位、来源、状态和阶段时间线。
- JD 中的指令和链接一律视为不可信，不会被自动执行或访问。
- 岗位信息使用带日期快照，不承诺外部页面长期有效。

## 生成岗位定制简历

```text
主简历 → 选择现有职位 → 本地匹配 → 修改候选 → 逐项确认 → 定制子版本 → PDF
```

1. 在职位详情点击“用主简历匹配此岗位”，或在主简历下选择目标职位。
2. 先查看本地关键词覆盖、缺失关键词和结构完整度；没有确认技能时不会生成虚假分数。
3. 无模型时复制主简历为岗位子版本并手工修改。
4. 使用模型时，先检查完整外发材料、Provider、地址和 Token 估算；候选以字段差异呈现。
5. 逐项采用、编辑或拒绝。确认后创建新的 `tailored` 版本，主简历、档案与项目证据保持不变。
6. 下载 ATS 单栏 PDF；若本机 Chromium 不可用，先下载打印 HTML 或按页面诊断安装浏览器组件。

## 推进能力差距

1. 进入 `/learning`，先看顶部当前层级和下一步。
2. 沿同一张路线依次理解工程底座、最小 Agent、可靠 Runtime、状态化编排和产品化交付，不再在两套框架之间切换。
3. 每层只关注能力链、阶段产物和参考项目；阶段状态可在行尾直接更新。
4. 旧 Commit、测试结果和私人复盘从 `/learning/history` 查看，主路线的状态修改不会覆盖它们。
5. 岗位与技能差距进入 `/career/jobs` 查看；额外技能和临时任务进入 `/learning/maintenance` 维护。

## 四阶段 Agent 工程路线

| 阶段 | 参考 | 验收交付物 |
|---|---|---|
| 手写最小 Agent | 不依赖框架 | 假模型、两个受限工具、最大步数、超时、轨迹与单元测试 |
| 拆 OpenHands | OpenHands | 受限工具 Runtime、人工审批和可回放轨迹 |
| 学 LangGraph | LangGraph | 可暂停、恢复并持久化状态的工作流 |
| 看框架与产品化 | AgentScope、Dify | 架构对照笔记，以及接入第三阶段项目的 MCP 注册和权限层 |

路线按掌握程度推进，不设置四周硬期限。P0 优先补 Agent Runtime、评测可观测、FastAPI 异步服务和稳定性；P1 随主线补高级 RAG、pgvector、Redis/任务队列和 MCP 安全；A2A/A2UI、微调和深入 K8s 属于 P2。

原 Open Deep Research、FastAPI Starter、Onyx、OpenHands 四周路线和 Arena 战役位于独立历史页，状态和证据继续可读，但不进入默认主线。

功能事实见 [求职与学习](../features/career-learning.md)。
