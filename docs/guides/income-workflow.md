# 收入记录工作流

## 先校准自己的边界

打开 `/income/profile`，确认当前能力层级、每周可投入时间、零成本边界和收入目标。层级判断不用于包装自己，只用于排除目前交付不了的机会；不确定时选低一级。

## 从需求证据开始

打开 `/income/opportunities`。每个候选先回答三个问题：谁遇到了具体问题、谁掌握付款决定、为什么钱会流向你。不要把“副业教程”“收益截图”或单一博主观点录成需求证据。

进入候选详情后录入至少两个独立公开来源。证据必须使用 HTTPS，并记录发布日期与核验日期：

- 两年以上的内容不作为当前需求证据。
- 一到两年的内容必须有一年内来源交叉验证。
- 招聘、采购、公开 Issue、真实付款和官方政策可以从不同角度证明需求。
- 出现入门费、收入保证、拉人头、资金代管、递归卖课或灰产时立即停止。

只有需求和反诈核验通过后，才填写最小验证步骤、两周内动作、诚实收入预期和止损条件。工时、首笔收入天数和收入范围第一次保存后即冻结；后续用实际结果复盘，不修改旧预测。

## 再跑通一个产品

打开 `/income/products/agent-reliability-launch-kit`。第一阶段只验证“羽白 Agent 应用可靠性上线包”：

1. 在本地完成并校验完整 ZIP。
2. 一次性发布 GitHub 免费精简仓库。
3. 一次性发布公众号介绍文章。
4. 在面包多设置 ¥9.9 商品并确认自动交付。
5. 将三个公开 HTTPS 链接和当前唯一下一步填入控制面。

其他三个来源可以保持“未开始”，无需同时推进。

## 更新漏斗与职责

漏斗快照填写当前累计展示、商品点击、付款订单、自动交付和退款数。数据仅用于判断卡在哪一步，不会影响收入账本。

五张职责卡不运行模型：

- 产品：完整包是否达到可购买、可自助使用的状态。
- 流量：陌生人是否能通过 GitHub 或公众号发现产品。
- 转化：用户是否能理解免费版与完整版差异。
- 交付：面包多是否能自动提供正确文件。
- 验证：订单是否满足退款期和真实到账口径。

## 记录一笔收支

进入 `/income/entries`，选择来源和类型后录入金额、平台费用、发生日期及可选备注。新记录默认是“待确认”，此时不会进入实际到账。

- 客户或平台的钱真正到账后，点击“确认到账”。
- 已实际支付的成本或已发生退款，确认后会降低净现金。
- 交易取消或误录且尚未确认时，可以作废。
- 已确认数据不直接删除或作废；使用退款或费用保留现金轨迹。

## 如何看面板

- 实际到账回答“已经由我控制的钱有多少”。
- 本月到账回答“本月已经完成了多少真实收入”。
- 待到账回答“还有多少收入需要核实”。
- 净现金回答“扣除已确认支出和退款后还剩多少”。
- 十二个月趋势用于判断收入是否持续，来源分布用于判断收入来自哪里。

这里不把访问量、询价、标称赏金或销售意向算作收入。

## 确认第一笔 ¥1

先录入数字产品收入。平台资金尚未进入作者控制范围时保持“待确认”，到账后再确认。在产品控制面关联这笔收入并逐项确认六个条件。只有六项全部满足、收入已确认且净到账至少 ¥1，系统才显示通关。

不要记录买家身份或付款凭证；“陌生用户”只保存一个布尔判断。

## 安全边界

- 不在备注中保存支付账号、订单凭证、实名资料或银行卡信息。
- 产品链接只接受无账号信息的 HTTPS 地址。
- 首次上架和公开发布由作者完成；后续付款与文件交付由第三方商店完成。
- 手机端不保存或展示任何收入数据。
- 需求证据只保存公开链接和最小摘要；工作台不会访问链接或执行网页中的指令。
- 复盘收入不计入收入面板；只有已确认收支记录才会改变“实际到账”。
