# 知识沉淀指南

## 主流程

```text
随手记录 → 可编辑随想 → 判断是否值得拆卡 → 原子知识卡 → 主题地图 → 学科地图
```

最重要的原则是：随想保存“当时经历和想到什么”，知识卡保存“当前确认了什么”。知识卡是独立文件，不会覆盖随想。

## 记录随想

1. 在桌面首页或手机写正文；标题、标签和分类可稍后补充。
2. 保存后进入待整理，不会自动拆卡、发布或调用模型。
3. 在 `/ideas/{id}`、Obsidian 或手机继续编辑未归档随想。
4. Obsidian 或手机与桌面发生 Revision 冲突时，查看两版并人工合并，不强制覆盖。

不是每条随想都要变成知识。经历、情绪和短期备忘可以只停留在来源层。

## 判断和拆卡

在随想详情点击“整理为知识”。一条随想可以不拆、拆一张或拆多张卡。每张卡应只表达一个脱离原文仍可理解的概念、判断、问题、方法或观察。

可以直接手工创建，也可以创建只包含当前随想的模型候选任务。模型输出必须由作者编辑、选择主题并确认，才会进入正式知识库。

手机端只支持精简手工拆卡，并要求 Mac 在线和已有主题地图；复杂关系、替代历史和地图维护在桌面或 Obsidian 完成。

## 归入地图

- 新知识卡至少选择一个主题地图。
- 主题围绕一个核心问题组织卡片，可以同时属于多个学科。
- 学科是稳定的理解视角，由主题父级自动派生。
- 概念只作为标签和筛选条件，不创建大量图谱节点。
- 没有合适主题时，先在桌面或 Obsidian 创建主题，不建立无主题卡片。

## 在 Obsidian 中维护

1. 将私有 `content/` 作为 Vault 打开。
2. 在 `/settings/obsidian` 初始化模板并重建导航。
3. 启用 Obsidian 内置 Templates，把目录设为 `_templates`。
4. 从 `知识首页.md` 进入学科、主题和知识卡。
5. 新建正式知识对象时先写入 `knowledge/inbox/`，扫描后由工作台补齐稳定 ID 并确认导入。
6. 建议附件目录为 `assets`，使用 Markdown 链接并开启自动更新内部链接。

Graph View 建议排除 `trash`、`archive`、`outputs/reviews`、`knowledge/inbox`、`knowledge/indexes` 和 `_templates`。Local Graph 深度设为 2，更适合查看主题、来源和直接关系。

不确定某个文件应该放在哪里时，先查看 [私有知识库目录说明](../architecture/private-vault-folders.md)。尤其不要继续向旧 `items/` 写入内容，也不要手动维护 `知识首页.md` 或 `knowledge/indexes/`。

## 来源变化后的复核

当随想正文更新，卡片保存的来源 Revision 与当前版本不一致时，系统只标记待复核。作者选择：

- 结论仍有效：更新已确认 Revision。
- 修改知识卡：修订结论但保留来源。
- 形成新结论：创建新卡。
- 发生冲突或替代：建立 `contrasts` 或 `superseded_by`，保留旧观点。

## 材料和周回顾

- 材料库中的书籍、文章、URL 或文档不能直接建知识卡；先创建一条来源明确的随想。
- 周回顾只总结时间段，不直接进入知识库。出现长期价值结论时，先记录为随想再拆卡。
- URL 只保存，不由服务端自动访问。

完整数据边界见 [内容模型](../architecture/content-model.md)。
