# 使用手册

本文按日常工作流说明如何使用羽白工作台。安装、启动和故障排查见 [运行与维护](OPERATIONS.md)。

## 日常入口

| 想做的事 | 入口 |
|---|---|
| 快速记录、查看待整理和近期状态 | `/` |
| 高级搜索、筛选和管理想法 | `/ideas` |
| 在正式知识层级中阅读与查看核心图 | `/knowledge` |
| 管理 Obsidian 模板、扫描和旧结构迁移 | `/settings/obsidian` |
| 管理材料与阅读队列 | `/library` |
| 创建周回顾 | `/reviews` |
| 转换公众号正文 | `/publish` |
| 创建视频项目和分镜 | `/video` |
| 管理求职和学习 | `/career`、`/learning` |
| 查看模型任务与成本 | `/models` |
| 管理手机、备份和系统设置 | `/settings` |

## 记录和整理想法

1. 打开根页面，在正文框写下临时想法。
2. 标题、标签和分类不是必填；没有标题时系统从正文生成。
3. 保存后内容进入“待整理”，不会自动公开、拆卡或调用模型。
4. 在首页内容流完成常见状态切换；需要标签、分类和日期筛选时进入想法库。
5. 打开详情页编辑完整 Markdown。若 Obsidian 已修改同一文件，工作台显示两版差异并拒绝覆盖。

状态含义：

- **草稿**：仍在整理，默认状态。
- **已成稿**：内容已经完成，但不会产生公网页面。
- **归档**：不参与日常内容流。
- **回收站**：文件已移入 `trash/`，仍可恢复。

永久删除需要再次输入确认词，只影响目标文件。Git 历史不是私人数据的备份方式。

## 使用 Obsidian 整理知识

### 第一次设置

1. 在 Obsidian 选择“Open folder as vault”，打开私有 `content/` 目录。
2. 在工作台进入“设置 → Obsidian 知识后台”。
3. 点击“初始化三种模板”和“重建分层导航”。
4. 在 Obsidian 启用内置 Templates，并把模板目录设置为 `_templates`。
5. 建议附件目录设置为 `assets`，链接格式使用 Markdown，开启自动更新内部链接。
6. 打开 Vault 根目录的 `知识首页.md`，从学科进入主题和知识卡。

### 新建知识卡

1. 在 `knowledge/inbox/` 新建笔记并插入“知识卡模板”。
2. 在 Obsidian 写清一个可以独立理解的结论、问题、方法或观察。
3. 回到 Obsidian 知识后台点击“扫描外部修改”。
4. 在知识模板收件箱补充至少一个原始来源，并选择所属主题和学科。
5. 确认导入后，工作台生成稳定 ID 并移动到正式 `knowledge/cards/`。
6. 点击“重建分层导航”，让 Backlinks 和 Local Graph 反映新关系。

### 新建学科或主题地图

- 学科地图定义一个稳定的知识边界。
- 主题地图聚合同一个核心问题，可以拥有多个父学科。
- 新笔记同样先进入 `knowledge/inbox/`，通过模板创建并在工作台确认。
- 工作台拒绝不存在的父级、循环父级和非法关系，不会覆盖正文。

### 查看图谱

- Obsidian 全局图用于查看正式知识结构，建议过滤 `knowledge/inbox`、`knowledge/indexes` 和 `_templates`。
- 打开一张知识卡后使用 Local Graph，深度设为 2，可查看主题、来源和直接关联观点。
- 工作台 `/knowledge` 只显示一张核心知识图。概念是筛选标签，不作为大量节点；点击知识卡后才展开来源。

### 整理旧结构

1. 在 Obsidian 知识后台查看 dry-run。
2. “已覆盖”表示旧学科/概念已经被正式知识卡承接；“需核对”和“未拆卡”不会被清理。
3. 检查文件名冲突和计划重命名。
4. 只有输入页面要求的确认词后才会应用。
5. 应用前系统在私有数据目录创建快照；需要时可恢复最近一次整理前版本。

不要直接编辑工作台生成的“工作台关联”区块。它会在重建时覆盖，而且不会进入正文、搜索、模型、周回顾、公众号或视频。

## 材料和统一搜索

- 材料库可以保存本地笔记、URL 或私有文档引用。
- URL 只记录，不会被服务端自动访问；打开必须由作者点击。
- 阅读后可从材料创建来源明确的新想法。
- 页面内按 `Cmd+K` 打开统一搜索，也可以进入 `/search` 使用无 JavaScript 回退。
- 搜索覆盖想法、知识卡、地图、文章、周回顾、材料、求职项目、职位、技能和视频项目，不调用模型。

## 周回顾

1. 在 `/reviews` 查看当前自然周记录。
2. 默认生成规则版回顾，结构中性，不使用公众号文风。
3. 同一自然周重复生成会更新同一份草稿，不覆盖原始记录。
4. 定时设置只在桌面服务运行时生效，并且只允许规则版。
5. 需要模型候选时，手动创建周回顾模型任务；确认前不会写入内容。

## 公众号创作

1. 在 `/publish` 选择想法、周回顾或文章。
2. 忠实转换直接使用原 Markdown，不调用模型。
3. 页面白色画布就是最终复制的正文范围；标题和摘要在公众号后台单独填写。
4. 点击“一键复制公众号正文”，检查图片内嵌数、需手动处理图片数和公式回退数。
5. 粘贴到公众号后台后，人工检查图片是否已重新托管、公式是否可读以及段落间距。
6. 若使用幻想栈风格候选，先预览外发内容并执行模型任务；原文与候选稿并排显示。
7. 只有点击“保存为文章草稿”才会新建 `article`，并通过 `parent_id` 关联来源。

## 视频策划与交接

1. 从文章进入 `/video` 创建项目。
2. 设置平台、画面比例、目标时长、表达类型、受众和风格。
3. 系统根据文章段落生成初始分镜，不调用模型。
4. 逐镜头修改时长、旁白、画面、字幕和素材引用。
5. 每次保存都会在私有项目目录原子更新 Storyboard YAML、旁白、SRT、Remotion Props 和 OpenCut brief。
6. 使用 Remotion 制作程序化动态图解，或把 brief、字幕和素材交给 OpenCut 人工精修。

当前不会自动渲染视频、转录音频或修改 OpenCut 时间线。

## 求职与学习

建议顺序：

1. 在候选人档案中维护目标岗位和已经核实的经历、技能与证书。
2. 在项目证据库记录项目职责、技术栈、问题、行动、结果和量化证据。
3. 导入简历版本并关联目标方向和项目证据。
4. 手动录入职位和 JD，更新阶段时间线。
5. 把职位要求关联到技能，标记现有证据、差距和优先级。
6. 为技能差距创建学习任务，关联想法、知识卡和项目证据。
7. 使用项目战役按 Quest 提交 Commit SHA、测试结果和私人复盘。

简历和 JD 的模型提取只生成候选内容。保存前必须核对，模型不能自动修改候选人事实或职位状态。

## Android 羽白工作台

- 手机首页提供“随手记 / 知识库”两个入口。
- 在线时可以新增文字、标签、分类和最多 5 张图片，并查看最近记录。
- 离线时新记录保存在设备队列；Mac 恢复后自动重试，也可点击“立即同步”。
- 知识区只读正式地图和有效知识卡，来源只展示标题、摘要和时间。
- Mac 或移动网关离线时知识不可读，但离线记录仍可继续排队。
- 可在桌面“设置 → 手机同步”撤销设备；撤销后需要重新配对。

完整安装和 Tailscale 设置见 [运行与维护](OPERATIONS.md)。
