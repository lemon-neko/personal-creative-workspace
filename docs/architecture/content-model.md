# 内容模型与生命周期

本文是随想、材料、周回顾、正式知识、文章、微信公众号和视频之间关系的权威说明。

## 三个职责层

```text
输入与原始记录
├── thought：可编辑随想，也是新知识卡的正式来源
├── material：外部材料，只能先派生为随想
└── weekly-review：中性周期汇总，不直接进入知识库或公众号

正式知识
随想 → 原子知识卡 → 主题地图 → 学科地图

独立创作
文章 → 微信公众号排版
     └→ 视频项目
```

### 输入与原始记录

- `thought` 保存当时的经历、观点、问题和碎片，可以持续修改。
- `material` 记录书籍、文章、URL 或文档等外部输入；需要沉淀时先从材料创建随想。
- `weekly-review` 汇总一段时间内发生的记录，只做中性回顾。
- 来源层不要求每条内容都被知识化、文章化或发布。

### 正式知识

- `KnowledgeCard` 保存人工确认、可以独立复用的原子结论。
- 卡片类型固定为概念、判断、问题、方法和观察。
- `KnowledgeMap(topic)` 围绕一个问题组织卡片，可以属于多个学科。
- `KnowledgeMap(subject)` 表示稳定的理解领域。
- 新卡必须关联至少一条未归档随想、至少一个主题和来源语义 Revision。
- 学科由主题父级派生；多父主题允许跨学科，循环关系禁止。

### 独立创作

- `article` 是独立文章草稿或成稿，不要求选择随想或知识卡。
- 作者可以参考来源和知识，但系统不强制维护文章素材图谱。
- 微信公众号是文章的导出方式，不是内容类型。
- 视频项目由文章派生，保存分镜和制作交接，不修改文章。

## 生命周期和显示语义

底层状态保持兼容：

| 类型 | `draft` | `published` | `archived` |
|---|---|---|---|
| 随想 | 待整理 | 已整理 | 已归档 |
| 文章 | 草稿 | 已成稿 | 已归档 |
| 周回顾 | 回顾草稿 | 已确认 | 已归档 |

`published` 只是本地生命周期状态，不代表公网发布。微信公众号发布仍由作者在外部后台人工完成。

## 来源与 Revision

创建知识卡时保存 `source_ids` 和 `source_revisions`。随想正文变化后，相关卡片进入“来源变化，待复核”，但卡片正文保持不变。作者可以：

- 确认结论仍有效，只更新来源 Revision。
- 修改已有知识卡。
- 创建新的独立结论。
- 明确建立 `contrasts` 或 `superseded_by` 并保留历史。

原始内容永远不会被拆卡、总结、润色、发布或视频流程覆盖。

## 兼容边界

- 原始想法中的旧 `subjects`、`concepts` 和 `relations` 只保持读取兼容，不再驱动图谱。
- 历史知识卡中的文章来源继续可读取和追溯，但新流程不会主动推荐文章作为拆卡来源。
- `/ideas/{article_id}` 兼容跳转至文章详情；周回顾旧详情跳转至回顾页面。
- 非文章不能执行微信公众号预览、润色或候选保存操作。

## 不进入正式知识的内容

- 尚未确认的模型候选。
- 周回顾、文章、视频项目和公众号导出。
- 归档、回收站、Obsidian 收件箱和生成导航。
- 只存在于旧元数据中的概念共现关系。

具体操作步骤见 [知识沉淀指南](../guides/knowledge-workflow.md) 和 [创作指南](../guides/creation-workflow.md)。
